# Milestone 29.1: Product Polish & UAT Critical Fixes

Status: **APPROVED — in progress. M29 Workstream B remains paused until this milestone closes.**

## 0. Why this milestone exists

M29 Workstream A shipped clean: full suite green, real signal handling, real worker self-healing.
Per standing process, a real user-acceptance test was run before starting Workstream B — the
actual built TUI, driven through a real terminal (tmux), using real installed provider CLIs
(Claude Code, Codex, Gemini), not mocks and not code inspection.

That UAT found the product was not production-honest. The single most serious finding: the
final artifact a real user reads to know whether their project worked — `REPORT.md` — fabricated
success (`COMPLETED`, `100/100`, `6/6 tests passed`, a list of files that were never written)
regardless of what actually happened. Several other real, reproducible defects were found
alongside it (interrupt not killing the real process, a Chat-tab keyboard trap, dashboard drift
from live state, two divergent project-start flows, and two distinct real provider CLI
integration failures).

M29 is paused. This milestone exists to fix what the UAT found, and only what it found (plus
whatever a full, honest product-designer-style pass over the TUI turns up) — no new AI
capabilities, no unrelated features. When this milestone closes, a second from-scratch UAT
(same method: real TUI, real terminal, no code inspection) must pass before Workstream B resumes.

## 1. Rules (governing every fix in this milestone)

- Do not add new AI capabilities or unrelated features.
- Focus only on correctness, usability, reliability, and user experience.
- Fixes are performed **one at a time** — no parallel work across issues.
- Every fix must include, before it is considered done:
  1. Root cause analysis
  2. Implementation
  3. Regression tests (where applicable)
  4. Documentation (ADR + CHANGELOG entry, per standing project convention)
  5. Commit
  6. Verification through the real TUI (not mocks)
- After all fixes are complete: a brand-new end-to-end UAT from scratch, using only the real
  application. Success is judged as a real user would judge it — not by inspecting code.

## 3. Per-fix reports

Each fix's root cause, implementation, and verification are recorded here as it completes,
following the same discipline established for M29 Workstream A.

### Fix #1 — REPORT.md must never fabricate results

See `docs/adr/ADR-0009-honest-execution-reporting.md` for the full root cause analysis and
design. Summary: fabrication existed at three layers — `ProjectLifecycleOrchestrator.
runProject()` writing a hardcoded fake report/scaffold unconditionally, four of
`VerificationPipeline`'s six steps being pure stubs that always reported `passed: true`, and
`ReasoningCoordinator.requestReasoning()` unconditionally returning `success: true` regardless of
whether the underlying provider execution actually succeeded. All three are fixed; `REPORT.md`
is now built entirely from real data and can honestly report `FAILED`.

### Fix #2 — Interrupt must terminate the real underlying provider process

See `docs/adr/ADR-0010-real-process-group-cancellation.md`. Summary: the real, installed `codex`
CLI's entry point is a Node.js launcher that forks the actual native binary as its own child.
SE-OS only ever held a handle to the launcher, so `cancel()`'s `child.kill()` killed the launcher
while the real work kept running, reparented and invisible. Fixed by spawning every real CLI
process detached (`detached: true`, its own process group) and killing the whole group
(`process.kill(-pid, signal)`) on cancel, timeout, and shutdown — every real cancellation path,
not just the one the UAT exercised. Verified two ways: a regression test that reproduces the exact
wrapper/grandchild shape and proves both that the old behavior left the grandchild running and
that the fix kills it; and a live interrupt against a real busy worker (Alice/Claude) through the
real built TUI, confirmed via `ps` that the real spawned process was actually gone immediately
after interrupting, with the on-screen "→ Interrupted Alice." matching reality.
